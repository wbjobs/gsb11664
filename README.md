# 复杂表单快照时间机

零框架静态应用，使用 DOM、IndexedDB、Web Worker 和 Canvas 实现复杂表单的无损快照、分支时间线、版本兼容、导入导出与时间旅行回放。

## 启动

```bash
npm start
```

然后打开本地 HTTP 服务输出的地址。模块 Worker 不能直接通过 `file://` 加载，因此需要使用静态服务器。

也可以用任意静态服务器在仓库根目录启动，例如：

```bash
python3 -m http.server 8080
```

## 测试

```bash
npm test
```

测试覆盖：

- 全量/Delta 压缩后的完整性哈希与无损重建。
- 回滚保护快照、分支恢复和历史状态保留。
- 字段删除、字段新增、类型变化和未知根字段的迁移/归档。
- v1 升级与未来结构版本降级。
- 同 ID 内容分叉和缺失父快照等导入冲突。
- 结构化差异和导出包往返。

## 功能说明

- **复杂表单**：三个字段分组，包含文本、数字、日期、选择、多选、复选、多行文本和可增删的里程碑。
- **快照创建**：必须命名；父快照可选，选择不同父节点会在 Canvas 时间线中形成分支。
- **自动保存**：编辑稿 450ms 防抖写入 IndexedDB；快照和草稿分开保存。
- **安全回滚**：恢复前自动比较当前编辑稿；不一致时先生成“回滚保护”快照，避免覆盖数据。
- **快照对比**：任意两个快照可比较，也可一键比较快照与当前编辑稿。
- **时间旅行**：点击“查看”进入只读预览；点击“回放”按时间顺序展示所有可重建快照。
- **导入导出**：导出包含完整快照链；导入会检查格式版本、ID 分叉、缺失父节点、Delta 链和状态哈希。
- **字段演进**：旧字段、类型转换前原值、未知字段和未来版本完整载荷分别进入 `retired`、`legacy` 或 `foreignState`。

## 数据设计

- IndexedDB：数据库 `snapshot-time-machine`，`kv` 对象仓库存放 `records` 和 `draft`。
- Web Worker：负责状态规范化、序列化检查、SHA-256 哈希、Delta 压缩、链重建、迁移和导入分析。
- 快照：`full` 保存完整状态；`delta` 保存排序 JSON Patch 风格操作、父哈希和压缩大小。每 4 层生成一次全量检查点。
- 校验：快照写入前计算规范化状态哈希；重建后重新应用 Delta 并校验哈希，任何损坏都会在时间线和列表中标红。
